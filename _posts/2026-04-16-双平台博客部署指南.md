# 使用 GitHub Pages 和内网 GitLab + Nginx 部署博客

折腾了大半天，终于把双平台博客自动部署整明白了。记录一下过程，方便以后查阅，也给有类似需求的朋友一个参考。

## 背景

我们的目标很简单：

- **GitHub Pages**：对外发布，博客公网可访问
- **内网 GitLab + Nginx**：供内部团队访问，文章先在内网审稿再发布到 GitHub

博客使用 Jekyll + Chirpy 主题，Git 管理，GitHub Actions / GitLab CI 自动构建。

## 方案一：GitHub Pages（对外）

### 1. 创建仓库

在 GitHub 上创建一个空仓库，命名为 `godsay1983.github.io`（改成你的用户名）。

```bash
git init
git remote add origin https://github.com/godsay1983/godsay1983.github.io.git
```

### 2. 本地初始化 Jekyll 博客

```bash
gem install jekyll jekyll-theme-chirpy bundler
jekyll new . --force
bundle install
```

> **注意**：如果遇到 `kramdown` 版本冲突，Gemfile 里只保留一行 `gem "kramdown-parser-gfm"` 就好，不要再单独指定 `kramdown` 版本。

### 3. 推送到 GitHub

```bash
git add .
git commit -m "init blog"
git push origin main
```

GitHub Actions 会自动检测 Jekyll 项目并构建站点，构建完成后博客就上线了：`https://godsay1983.github.io`

## 方案二：内网 GitLab + Nginx Docker（对内）

### 整体架构

```
本地 Git 仓库
    ↓ git push
GitLab 远程仓库
    ↓ Webhook 触发
GitLab Runner（shell executor）
    ↓ bundle exec jekyll build
Nginx Docker 容器（ port 4000）
```

### 1. 服务器上安装 GitLab Runner

```bash
# 下载 runner
curl -L https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh | sudo bash
sudo apt-get install gitlab-runner

# 注册 runner（交互式）
sudo gitlab-runner register
```

注册时需要输入：
- GitLab URL：`http://192.168.109.202:8080`
- Token：在 GitLab 项目 Settings → CI/CD → Runners 里找
- Executor：**`shell`**（不是 docker！）

### 2. 服务器上安装 Ruby 和 Jekyll

```bash
sudo apt-get install ruby ruby-dev bundler
sudo gem install jekyll jekyll-feed jekyll-theme-chirpy
```

### 3. 服务器上解决 bundler 权限问题

runner 默认用 `gitlab-runner` 用户运行，bundler 安装 gems 时会遇到权限问题。创建一个用户目录给 bundler：

```bash
sudo mkdir -p /home/gitlab-runner/.gem/ruby/3.2.0
sudo chown -R gitlab-runner:gitlab-runner /home/gitlab-runner/.gem
```

或者直接给系统目录加权限：

```bash
sudo chmod 777 /var/lib/gems/3.2.0/cache
```

### 4. 启动 Nginx Docker 容器

```bash
docker run -d \
  --name blog-server \
  -p 4000:80 \
  -v /data/blog:/usr/share/nginx/html:ro \
  --restart unless-stopped \
  nginx:alpine
```

- 博客内容部署到 `/data/blog` 目录
- 容器内 nginx 监听 80 端口，映射到宿主机的 4000
- `-v /data/blog:/usr/share/nginx/html:ro` 表示把宿主机的 `/data/blog` 挂载为只读的 web 目录

### 5. 创建 GitLab 项目并添加 CI 配置

在 GitLab 上创建一个公开项目（私有项目 Pages 需要 Premium），获取 HTTP clone URL。

本地博客仓库添加 GitLab 远程：

```bash
git remote add gitlab http://192.168.109.202:8080/caozhipeng/blog.git
```

在项目根目录创建 `.gitlab-ci.yml`：

```yaml
variables:
  GEM_HOME: /home/gitlab-runner/.gem/ruby/3.2.0
  GEM_PATH: /home/gitlab-runner/.gem/ruby/3.2.0
  JEKYLL_ENV: production

pages:
  stage: deploy
  script:
    - bundle install
    - bundle exec jekyll build
    - rm -rf /data/blog/*
    - cp -r _site/. /data/blog/
    - echo "部署完成 → http://192.168.109.202:4000"
  artifacts:
    paths:
      - public
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
```

推送到 GitLab：

```bash
git push gitlab main
```

GitLab 会自动触发 Pipeline，runner 执行 Jekyll 构建，构建结果复制到 `/data/blog`，Nginx 直接 serving。

### 6. 确保 runner 可用

如果 Pipeline 报 `no runners available`：

1. GitLab → 项目 → Settings → CI/CD → Runners
2. 确认 runner 已激活，且勾选了 **"Run untagged jobs"**

## 设置双推送

如果想一条命令同时推送到两个平台，可以给 origin 添加多个 push 地址：

```bash
# 先查看当前 remote
git remote -v

# origin 现在应该指向 GitHub，添加 GitLab push 地址
git remote set-url --add --push origin http://192.168.109.202:8080/caozhipeng/blog.git
```

验证：

```bash
git remote -v
# origin 应该显示两个 push URL
```

之后只需 `git push origin main` 就会同时推送到 GitHub 和 GitLab。

## 写文章并发布

```bash
# 创建新文章
hexo new post "我的新文章"
# 或直接创建 Markdown 文件
vim _posts/2026-04-16-my-new-post.md

# 推送（同时推送到两个平台）
git push origin main
```

## 踩坑总结

### 1. Bundler 权限问题

runner 用户无法写入系统 gems 目录，报错：
```
Bundler::PermissionError: There was an error while trying to write to `/var/lib/gems/3.2.0/cache`
```

解决：设置 `GEM_HOME` 环境变量指向有权限的目录。

### 2. kramdown 版本冲突

Gemfile 里同时有 `github-pages` 和 `kramdown >= 2.4.0` 会冲突，`github-pages ~> 228` 依赖 `kramdown = 2.3.2`。

解决：删除显式的 `kramdown` 行，只保留 `kramdown-parser-gfm`。

### 3. Docker vs Shell Executor

最初用了 Docker executor，虽然 CI 容器内能访问 Docker socket，但挂载 `/data/blog` 时遇到权限问题。换成 Shell executor 后简单多了。

### 4. Runner 标签问题

注册 runner 时如果填了标签，`.gitlab-ci.yml` 里也要加对应的 `tags`；或者直接在 GitLab 网页上勾选 **"Run untagged jobs"**。

## 效果

- **公网**：`https://godsay1983.github.io`（GitHub Pages）
- **内网**：`http://192.168.109.202:4000`（Nginx Docker）

写完文章 `git push origin main` 一次搞定两个平台。
